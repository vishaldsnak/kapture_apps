Legacy vs Kapture XML structure

One merged structure per channel for the RMI Export and MNAO Data Export tools. It holds every element and attribute found in any exported document, so a single document may carry only some of them.

Service InformationService ManualsWiring DiagramsOther Service Manuals
Legacy onlyKapture onlySame element, name differs

What changed

  • The root element and its attribute changed: CONTENT RECORDID is now content contentid.
  • The header elements come from Kapture, so the legacy date, locale, version and repository elements are not in the export.
  • The channel elements match legacy, apart from the differences marked in each table.
  • DOCUMENTID and CATEGORIES are unchanged.

How to read it

  • "Seen in" counts the documents with that element, against all documents read for that tool. The count covers the exported XML, after each tool's filter.
  • Kapture often leaves out an empty element that legacy always wrote, so a lower Kapture count does not by itself mean lost data.
  • ATTACHMENT appears in both forms in Kapture: a plain file name, or the five child elements shown.
  • Values are written in CDATA in both, so rich text reads as HTML. Kapture dates, flags and ids in the header stay plain, as they did in legacy.
