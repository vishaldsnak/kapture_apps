Rules for every call

  • A 2xx is not success. Bulk answers 200 with COMPLETED_WITH_ERRORS. Single writes can answer HTTP 200 with status "500" in the body. Read the per-record status, and read back anything load-bearing.
  • Writes replace the whole row. On update-article-tab and publish-article, an omitted field becomes NULL.
  • Read shape is not write shape. The read returns numbers for versions, slash dates, and an object for one-entry lists. Convert before writing.
  • Refkeys travel with names. A nameless entry is accepted, then renders as undefined.
  • Never resend a timed-out bulk POST. Reconcile by correlation id or k_article.
  • Retry the request, not the record. 429, 5xx and no answer are request failures; retry with backoff. A failed record inside a 200 waits for the next run. Job 11 does not retry 500.
  • Strip markup before sending. script, meta, iframe, object, embed, link, on* handlers, and javascript: or vbscript: URLs are rejected by the sanitizer.
  • Rate limit. 100 requests per minute per client IP and exact path. 429 returns Retry-After: 60.

Key terms

contentIdThe channel id from k_content_type (by documentid_prefix). It differs per environment. Never hard-code it.
articleIdThe document id, such as SI1123.
idk_article primary key. Differs per version. Not the articleId.
primaryLocaleThe master's locale.
translatedLocale / translateLocaleWith d on masters and reads; without d on translation writes.
pubFlagPer-record publish intent.
articleStateOn update: a lookup key holding the current state, not a target.

Login

Every call needs the Bearer token from this one call.

Login

POST/kauthor-api/cms-check

Returns the session token and the logged-in user's profile.

Used byJob 4Job 9Job 10Job 11DMTMDM
Header
Content-Type: application/json
  • The token is at response.userSessionToken, not at data.
  • A 2xx with no token is a failed login. DMT and Job 10 stop there.
  • The profile is at response.userCmsRoles[0]. createdBy / modifiedBy = firstName + lastName, never the e-mail.
  • uploadedBy on attachments = userPkId.
  • A saved sample token runs 2 hours (iat to exp). On 401, log in once and retry.
  • Java 8 callers must force TLS 1.2/1.3 with -Dhttps.protocols and -Djdk.tls.client.protocols.

Bulk article import

The main load path. The body is always a JSON ARRAY of articles, and each record succeeds or fails on its own.

Bulk create

Job id BAI-

POST/kauthor-api/api/v1/bulk-article-import

Creates master articles. legacyDocumentId becomes the Kapture article id.

Used byJob 10DMT
Query
contentId = channel content id (from k_content_type)
Query
batchSize = how Kapture splits the request across its workers
Query
publish = always false; it overrides every record. Use pubFlag per record
Header
Authorization: Bearer <token>
Header
X-Correlation-ID = our own id, needed to recover a timed-out request
  • legacyDocumentId is mandatory. Kapture will not mint an id.
  • The idempotency key is contentId + legacyDocumentId + primaryLocale.
  • Create accepts articleState Unpublished only; set pubFlag to publish.
  • SKIPPED_DUPLICATE does not return id or articleVersion. Recover them from k_article.
  • Match the duplicate case on 409 AND errorCode, never on 409 alone.
  • Validation stops at the first problem. One reported error does not prove it is the only one.
  • Category arrays tag the document. The CSV fields map nothing, and each entry needs selected: true.
  • One unknown category refkey fails the whole record.

Bulk update

Job id BAU-

POST/kauthor-api/api/v1/bulk-article-import/updates

Updates masters. Kapture resolves the target from articleId + locales and writes the next version.

Used byJob 10DMT
Query
contentId = channel content id (from k_content_type)
Query
batchSize = how Kapture splits the request across its workers
Query
publish = always false; it overrides every record. Use pubFlag per record
Header
Authorization: Bearer <token>
Header
X-Correlation-ID = our own id, needed to recover a timed-out request
  • Since 2026-08-25, leave id and articleVersion OUT. Absent means Kapture resolves them; sending either goes back to id/version targeting. The sample above carries none of them for that reason.
  • If you do send id, it must be a quoted string. A number is rejected.
  • articleState stays mandatory and is a lookup key: send the CURRENT state from k_article, not the target state.
  • A master sends primaryLocale and translatedLocale both set, but k_article stores translated_locale NULL. Lookups must OR the two forms.
  • A failed record may carry id and version (UPDATE_ARTICLE_ERROR). Read them when present, never require them.
  • Parse a version out of a message with (\d+(?:\.\d+)*) so the full stop is not captured.
  • After a publish failure the draft is at x.1 and live stays at x.0. Check articleState and publishedVersion.

Bulk translate

Job id BAT-

POST/kauthor-api/api/v1/bulk-article-import/translations

Creates or updates a translation. The same call does both.

Used byJob 10
Query
contentId = channel content id (from k_content_type)
Query
batchSize = how Kapture splits the request across its workers
Query
publish = always false; it overrides every record. Use pubFlag per record
Header
Authorization: Bearer <token>
Header

Temp attachment upload

POST/kauthor-api/api/temp-attachment/upload

Uploads files first. The article then references each tempAttachmentId.

Used byJob 9 (old form)Job 10DMT
Form
attachments[i].file
Form
attachments[i].clientAttachmentId = our id, used to match the answer
Form
attachments[i].legacyDocumentId
Form
attachments[i].locale
Form
uploadedBy = session userPkId
Old form
multipartFiles + uploadedBy (Job 9 only)
  • Do not send attachments[i].articleVersion. The finalizer validates it and kills the record.
  • One upload per attachment node. Sharing a tempAttachmentId across two nodes fails the record.
  • A temp expires after 2 hours, and a successful save finalizes it for good.
  • Size limit is undocumented. 12 files or fewer landed, 15 or more bounced. Job 10 ships 10 files / 8 MiB and bisects on rejection.
  • Sanitise .. out of file names (open defect). One bad file fails the whole request and the 500 names none of them.
  • The article can report success while its upload failed. Check the upload result itself.
  • Correlate on clientAttachmentId, never on position.
  • attachmentAction values: NEW, KEEP, REPLACE, DELETE.

Single-document APIs

Used by MDM and DMT, and by Job 9 for writes. These writes replace the whole row, so an omitted field becomes NULL.

Create article

POST/kauthor-api/add-article-tab?contentId=

Creates one document, always Unpublished. The document id comes back in the response.

Used byJob 9MDM (SI Data Import)
Query
contentId = channel content id
  • The result is nested at response.articleSaveResponse.
  • Under concurrency this path can write a duplicate articleId silently. That is why Job 9 ran single threaded.
  • Job 9 is superseded by Job 10 (2026-10-29).

Update article

PUT/kauthor-api/update-article-tab?contentId=

Rewrites a master. On a published document it creates a new unpublished version.

Used byJob 9MDM
Query
contentId = channel content id
  • An omitted field becomes NULL. Echo the read and change only what you mean to change.
  • Write shape = 22 fields. A Published document adds isUpdateArticle: true and publishedVersion (24). Unpublished omits both keys entirely.
  • id, articleVersion, publishedVersion and article_state come from k_article. The read has no id and returns versions as numbers.
  • Send only selected: true categories, each with its name. A missing name renders as undefined in KAuthor.
  • articlelistusergroup, articlelistview and both category lists must be arrays, even if the read gave one object.
  • expireDate and reviewDate must be yyyy-MM-dd HH:mm:ss.
  • Masters only. Translations go through save-translate-article.

Save translation

POST/kauthor-api/save-translate-article?contentId=

Creates or updates one translation.

Used byMDM
Query
contentId = channel content id
  • There is no articleSaveResponse here. Read sectionKey (document), latestVersion and documentPrimaryID (k_article id).
  • Reading only the nested shape reports failure on a write that worked.
  • Open: articlelistusergroup sent here was found not persisted on SI1125/en_EU. Do not echo a read blindly, because a published translation can come back without its groups.

Publish article

POST/kauthor-api/publish-article

Publishes the version an update just created. Use it only when the updated version was Published.

Used byMDM
Body
Master: as shown. Translation: add translateLocale
  • This call rewrites the row too. Send the UPDATED content, not the read taken before the update.
  • Set the title in both places: the schema node's TITLE and the article-level title.
  • Publish the version the update created: re-read latest_version='Y'.
  • Translation numbering: update makes 0.3, publish makes 1.0 again.

Read latest article

GET/kauthor-api/latest-article/{articleId}/{contentId}/{locale}

Returns the latest version for a locale without being told the version or state.

Used byMDMDMT
Path
articleId, contentId (channel), locale
  • k_article's id is not in the response, so the k_article read stays.
  • Versions arrive as numbers: 4.0 comes back as 4. Take version strings from k_article.
  • A lone user group, view or category comes back as an object, several as an array.
  • Translations use translateLocale (no d). Compare values and read both keys.
  • An unpublished translation is thin: no articleState, publishedVersion, dateAdded, createdBy or modifiedBy.
  • expireDate and reviewDate come as MM/dd/yyyy HH:mm:ss. Convert these two fields before a write.

Unpublish

POST/kauthor-api/unpublish-this-versions

Unpublishes one document. Content, categories and attachments stay as they are.

Used byDMT (delete processing)
Config

Used byJob 4MDMDMT (API write mode)
Query
locale
Body
emailId = the login e-mail
  • A 2xx does not prove the row was written. DMT reads k_categories back (4 attempts, 1.5 s apart).

Update category

POST/kauthor-api/updateCategoryByCatRef?categoryRef=&locale=

Changes a category's name and description.

Used byJob 4MDMDMT (API write mode)
Query
categoryRef, locale
  • POST, not PUT. PUT on this URL returns 500.
  • There is no parentRefKey, so a category cannot be re-parented.
  • The row is rewritten, so k_categories.date_added resets to the update time.
  • Job 4's shipped properties still point at the dead /Kapture-Author path. Fix them before any re-run.

Workflow history, case links, recommendations

Job 11 only. The calls are one record at a time and run at about 90 per minute.

Add history entry

POST/kauthor-api/add-article-comments

Saves one history entry or plain comment for an article version.

Used byJob 11 (API mode; DB is the configured default)
Body
currentArticleAction: Created, Edited, Reverted, Published, Unpublished or Approved; other labels are stored as sent
Config
activity.wfh.write.mode = DB writes k_article_comments directly
  • The new id is the first word of message.
  • The 6 standard actions dedupe on article + locale + version + action: you get 200 and the existing id.
  • There is no original timestamp field, and standard actions store the signed-in user.
  • No validation: an unknown article or version is saved anyway.

Used byJob 11

  • No dedup and no update API. Tracking must prevent a resend.

Create recommendation

POST/kauthor-api/api/recommendations

Scope DOCUMENT targets one article; CONTENT_TYPE targets a channel (send contentChannel instead).

Used byJob 11

  • Treat an errorMessage in a 200 as a failure.

Open with Kapture

  • Two dots in attachment file names give a 500 on upload.
  • Bulk publish resolves the wrong row on a translated document (highest id, no locale filter), which gives the 409.
  • Rollback-only publish failure on bulk update: the draft commits, the publish does not.
  • Upload size limit is undocumented; the working caps are ours.
  • update-article-tab and translations (A11): by design or defect is unconfirmed in the tracker. We use save-translate-article either way.
  • QA issues K2 and K5 (SC SVG, timeouts) stay open in the QA failures report.
